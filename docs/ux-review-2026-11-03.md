# HUAKEY CRM 真实用户视角 UX 走查报告

**日期**：2026-11-03
**走查方式**：本地测试实例（隔离库 `huakey_crm_test`，`frontend/scripts/start-e2e-server.mjs` 启动，后端 5000 / 前端 5173）+ 静态代码取证。生产环境零请求、零改动。
**走查账号**：demo_sales（销售）、demo_manager（主管）、demo_admin（管理员，测试库中原本被禁用，已在测试库重新启用）、demo_purchase（采购）。
**证据标注**：【实测】= 浏览器真实操作复现；【静态】= 代码/数据直接取证；截图存于本地 `tmp/ux_shots/`（不入库）。

---

## 一句话结论

系统的安全基座（数据权限、并发锁、幂等）做得扎实，但**「销售建客户 → 落潜客池不归自己」「主管看不到无主潜客」「发票后端齐全前端无入口」「登记回款要手工抄金额」这四类断链**，让真实的日常操作路径绕远、反直觉，其中多数修复成本只有几行代码。

## Top 10：改起来便宜且效果明显（建议先做）

1. **U-03** `listRoles` 加 `WHERE deleted_at IS NULL` —— 一行 SQL，消除管理员视角的重复角色。
2. **U-05** 合同详情日期 `dayjs().format('YYYY-MM-DD')` —— 两处插值，财务不用再猜日期。
3. **U-06** 登记回款弹窗加三行只读金额（合同额/已回/剩余）——数据详情页已有，纯前端展示。
4. **U-01** 新建客户 toast 说明去向 + 附「去转为正式」链接——一行文案先止血，归属规则再议（见下节）。
5. **U-08** 商机表单按权限拉 user list（销售不请求/不显示「负责人」）——一个 v-if + 一个条件请求。
6. **U-10** 目标页 SQL 加角色过滤——一个 WHERE 条件。
7. **U-11** 删除用户/角色确认框补充后果文案——两处模板字符串。
8. **U-07** 客户列表删除重复的那组「我的/全部」切换——删一段模板。
9. **U-16** 折扣文案改百分比 + 报价路由标题区分新建/编辑——文案级改动。
10. **U-20** 禁用账号登录文案改「账号已被停用」——后端一处分支（同时保留账号存在性模糊化可另行评审）。
