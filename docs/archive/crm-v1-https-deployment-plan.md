### 1.1 NAS DSM 环境

| 项目 | 当前状态 |
|------|----------|
| NAS 型号 | 群晖 NAS |
| DSM 版本 | 已安装 Container Manager |
| DSM 端口 | 5000（HTTP）/ 5001（HTTPS） |
| 80 端口 | 已被 DSM nginx 占用 |
| 443 端口 | 已被 DSM nginx 占用 |
| CRM 端口 | 6789（HTTP 明文） |

### 1.3 当前风险

| 风险 | 影响 |

| 无 SSL 证书 | 浏览器安全警告 |
| Cookie 非 Secure | Token Cookie 可被 HTTP 劫持 |

## 2. 方案评估

### 方案 A：群晖 DSM 反向代理（推荐）

```
用户浏览器
   ↓ HTTPS 443
群晖 DSM 反向代理（内置 nginx）
   ↓ HTTP 6789
CRM App 容器
```

**实现方式**：通过 DSM 控制面板 → 登录门户 → 高级 → 反向代理

**优点**:
- ✅ 无需额外容器，使用 DSM 内置 nginx
- ✅ DSM 自动管理 SSL 证书（Let's Encrypt 或自签）
- ✅ 80/443 已被 DSM nginx 占用，天然兼容
- ✅ 配置简单，GUI 操作
- ✅ DSM 自动续期证书
- ✅ 支持 WebSocket

**缺点**:
- 依赖 DSM 服务，DSM 重启时反代短暂中断

### 方案 B：Docker nginx 容器

```
用户浏览器
   ↓ HTTPS 443
Docker nginx 容器（需改端口）
   ↓ HTTP 6789
CRM App 容器
```

**实现方式**：新增 nginx 容器，映射 443 端口

**优点**:
- 独立于 DSM，可自定义 nginx 配置
- 支持灰度发布（nginx-canary.conf）

**缺点**:
- ❌ 80/443 已被 DSM nginx 占用，需改端口或停用 DSM nginx
- ❌ 需手动管理 SSL 证书
- ❌ 增加一个容器，运维复杂度增加
- ❌ DSM 更新可能冲突

### 方案 C：App 容器内置 HTTPS

**不推荐**：增加应用复杂度，违反职责分离原则。

---

## 3. 推荐方案：方案 A（群晖 DSM 反向代理）

### 3.1 推荐理由

1. **零端口冲突**：80/443 已被 DSM nginx 使用，方案 A 直接复用
2. **证书自动化**：DSM 支持 Let's Encrypt 自动申请和续期
3. **运维简单**：GUI 配置，无需维护额外容器
4. **生产可用**：群晖反向代理为生产级 nginx，稳定可靠

### 3.2 部署步骤（待执行）

```
步骤 1: DSM 控制面板 → 安全性 → 证书
        - 申请 Let's Encrypt 证书（需域名）
        - 或导入自签证书（内网 IP 访问）

步骤 2: DSM 控制面板 → 登录门户 → 高级 → 反向代理
        - 新增反向代理规则
        - 来源协议: HTTPS
        - 来源主机名: 192.168.0.200（或域名）
        - 来源端口: 443（或自定义如 8443）
        - 目标协议: HTTP
        - 目标主机名: localhost
        - 目标端口: 6789

步骤 3: 修改 CRM 应用配置
        - CORS_ORIGIN 改为 https://192.168.0.200（或域名）
        - Cookie Secure 标志启用

步骤 4: 验证
        - 访问 https://192.168.0.200
        - 验证证书有效
        - 验证 API 请求正常
```

### 3.3 证书选项

| 选项 | 适用场景 | 说明 |
|------|----------|------|
| Let's Encrypt | 有公网域名 | 需 DDNS + 80 端口可访问 |
| 自签证书 | 内网 IP 访问 | 浏览器需手动信任 |
| 群晖默认证书 | 内网 | DSM 自带，可复用 |

## 4. 配置变更清单（执行时使用）

### 4.1 App 配置变更

| 配置项 | 当前值 | 目标值 |
|--------|--------|--------|
| `CORS_ORIGIN` | http://192.168.0.200:6789 | https://192.168.0.200 |
| `COOKIE_SECURE` | 未设置 | true |
| `Helmet CSP` | upgradeInsecureRequests: null | 保持 null 或移除 |

### 4.2 DSM 配置变更

| 配置项 | 操作 |
|--------|------|
| 反向代理规则 | 新增 HTTPS 443 → HTTP 6789 |
| SSL 证书 | 申请或导入 |
| HSTS | 启用（可选） |

---

## 5. 风险与注意事项

| 风险 | 影响 | 缓解 |
|------|------|------|
| DSM 重启中断 | 反代短暂不可用 | DSM 维护窗口执行 |
| 证书过期 | 浏览器警告 | 启用自动续期 |
| CORS 配置错误 | 前端无法访问 | 部署后验证 |
| Cookie Secure 标志 | HTTP 下 Cookie 不发送 | 必须配合 HTTPS 使用 |

---

## 6. 验收标准

| 验收项 | 标准 |
|--------|------|
| HTTPS 访问 | https://192.168.0.200 可正常加载 |
| 证书有效 | 浏览器无安全警告 |
| API 正常 | 登录、CRUD 接口正常 |
| WebSocket | 如有实时通信，连接正常 |
| HTTP 跳转 | HTTP 自动跳转 HTTPS（可选） |
