## 四、已实施的修复

### 4.1 侧边栏改为抽屉式覆盖层（M-01）

这是本次唯一需要改布局逻辑的修复，不只是 CSS。

| 文件 | 改动 |
|------|------|
| `views/layout/index.vue` | 新增 `isMobile`（`matchMedia('(max-width: 768px)')` 监听，含旧版 Safari `addListener` 回退）、`mobileMenuOpen` 状态；路由切换后自动收起抽屉；顶栏按钮在移动端改切抽屉而非折叠；新增遮罩层 |
| `components/layout/Sidebar.vue` | 新增 `isMobile` / `mobileOpen` props；移动端强制展开显示完整菜单，避免折叠态只剩图标 |
| `styles/apple.css` | `.sidebar--mobile` 固定定位 + `translateX(-100%)` 抽屉化，`.sidebar--open` 滑入；`--duration` / `--ease-out` 过渡 |

> 断点常量在 `layout/index.vue` 与 `apple.css` 两处必须保持一致，代码中已加注释说明。

### 4.2 详情抽屉近全宽（M-02）

`apple.css` 768px 断点内覆盖 `size` 内联宽度：

```css
.el-drawer.rtl, .el-drawer.ltr { width: 92% !important; }
.el-drawer.ttb, .el-drawer.btt { height: 92% !important; }
```

### 4.3 统计卡片响应式降列（M-03 / M-04 / M-06）

- `components/dashboard/StatsCards.vue`：`:span="6"` → `:xs="24" :sm="12" :md="6"`（16 处）；`:span="8"` → `:xs="24" :sm="12" :md="8"`
- `styles/apple.css`：新增 1024px 断点（`.stat-cards` 两列）；768px 断点内降为单列，符合规范 §9.1「4 列 / 2 列 / 1 列」

### 4.4 顶栏小屏收敛（M-05）

`components/layout/HeaderBar.vue`：面包屑与「最近访问」入口加 `hide-mobile`，复用已有工具类，小屏只保留汉堡键、搜索、通知、头像。

### 4.5 新增 token

`styles/apple.css` 新增 `--overlay-backdrop: rgba(0, 0, 0, 0.35)`，供移动端抽屉遮罩使用，延续色板 token 化路线（不在组件内写死色值）。

## 八、结论

改造前项目**实际上没有移动端适配**——只有 768px 断点里几条零散规则，而最关键的侧边栏是固定 230px，在手机上直接不可用。本次补齐了断点体系、把侧边栏改为抽屉、收敛了顶栏与统计卡片栅格。

**验证强度已升级，但仍未完全闭环：**

| 阶段 | 手段 | 结果 |
|------|------|------|
| 初版 | 源码静态审查 | 发现 9 项问题 |
| 补充 | E2E 真实页面自动化（16 用例） | 通过，**并额外暴露 3 个被掩盖的真实缺陷**（R-01/R-02/R-03），已修复 |
| 剩余 | 真机人工走查（§七点五 5 项） | ⚠️ **未执行** |

**因此本报告仍不能作为移动端最终验收依据**——布局层面的缺陷已由自动化守住，但触摸手势、真机字体、iOS 安全区这三类问题只有真机能发现。§七点五 的 5 项人工确认完毕后方可标记完成。
