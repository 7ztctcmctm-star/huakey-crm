## 第 3 层 · 功能与端到端

### 3.1 Playwright E2E（测试库 huakey_crm_test，SKIP_CAPTCHA=true 仅测试环境）

- 配置：`frontend/playwright.config.js`——自举后端(5000)+Vite dev(5173)，**克隆本地 dev 库为测试库**（`scripts/start-e2e-server.mjs`，SKIP_DB_SETUP 默认 false），与生产库完全隔离。
- 实跑（chromium 单项目，按项目约定本机只信 chromium）：**50 用例 = 12 通过 / 34 失败 / 4 未运行**（exit 1）。
- **失败根因已锁定且为同一根因**：登录 fixture `e2e/fixtures/auth.js:83` 以 `demo_admin` 登录 → HTTP 401「用户名或密码错误」。
  证据链（测试库只读 SELECT）：
  ```json
  { "username": "demo_admin", "status": 0, "is_demo": 1, "role": "super_admin" }   // huakey_crm_test.sys_user
  ```
  迁移 `127_disable_demo_admin.sql` 把 demo_admin 置 status=0 → 本地 dev 库执行过 127 → E2E 克隆继承 → `seed-demo.js` 用 INSERT IGNORE（幂等）**不会恢复状态位** → 登录查询 `WHERE u.status = 1` 查无此人 → 401。
- 通过的 12 例为登录页渲染/表单校验/跳转等无需登录态的用例（login.spec 等）。
- 结论：**E2E 回归防线自 11-02 部署批次起失效（迁移 127 与测试基建未联动）**，非本批业务代码缺陷。详见问题清单 P1-1。
