## 一、背景与问题

阶段映射在 5 个文件重复 7 处（含两种数据结构、一处截断），任何阶段变更都要改多处，漏一处即口径不一致。扩为 8 阶段须同时建立单一事实源。

## 二、现状（实测）

现 **6 阶段**（`crm_opportunity.stage TINYINT`）：

| stage | 名称 | 概率 |
|---|---|---|
| 1 | 询盘 | 10% |
| 2 | 需求确认 | 25% |
| 3 | 方案报价 | 50% |
| 4 | 谈判 | 75% |
| 5 | 成交 | 100% |
| 6 | 失败 | 0% |

重复映射位置（2026-09-24）：`analysisService.js:213/245`、`reportAnalyticsService.js:63（数组）/447（对象）`、`searchRouteService.js:9`、`teamDashboardService.js:408（仅前 4 阶段，截断）`；`opportunityService.js` 顶部另有 STAGE_MAP / 概率 / 回退规则。

自动推进点：报价审批通过 → **stage 3（方案报价）**（`quoteService.js:358`）。

## 三、8 阶段提案（推荐）

结合外贸销售实际，在「谈判」与「成交」之间补入**合同审批、合同签署**两个真实环节；流失作为第 8 阶段：

| 新 stage | code | 名称 | 概率 | 分组 |
|---|---|---|---|---|
| 1 | `inquiry` | 询盘 | 10% | open |
| 2 | `qualification` | 需求确认 | 25% | open |
| 3 | `proposal` | 方案报价 | 50% | open |
| 4 | `negotiation` | 商务谈判 | 65% | open |
| **5** | `contract_review` | **合同审批（新增）** | 80% | open |
| **6** | `contract_signing` | **合同签署（新增）** | 90% | open |
| 7 | `won` | 成交（原 5） | 100% | **won 终态** |
| 8 | `lost` | 流失（原 6 失败） | 0% | **lost 终态** |

- 前进：1→…→7；回退：仅 open 阶段可回退（沿用现 BACKWARD_RULES），7/8 不可回退。
- 与合同域联动：商机进入 stage 5 对应合同提交审批、stage 6 对应合同签署、stage 7 对应成交（与 RFC-R10 状态机对齐）。

> 已拍板采用上表（**lost 占第 8**）。备选「7 推进阶段 + lost 旁路标记」未采纳。

## 四、数据迁移映射

| 旧 stage | → 新 stage |
|---|---|
| 1 询盘 | **1** |
| 2 需求确认 | **2** |
| 3 方案报价 | **3** |
| 4 谈判 | **4** |
| 5 成交 | **7** |
| 6 失败 | **8** |
| —（新增，存量无） | 5 合同审批、6 合同签署 |

特点：**旧 1–4 编号不变**，报价审批自动推进的 stage 3 不受影响；仅成交/失败两个终态右移，新增 5/6。迁移须先干跑、保留映射表以便回滚。

## 五、单一事实源收敛

1. 新增 `backend/constants/opportunityStage.js`：编号 / code / 名称 / 概率 / 前进回退规则 / 分组，作为唯一事实源；
2. 上述 5 文件 7 处全部改为引用（含截断的 teamDashboard）；
3. 加 grep 守卫测试：全仓出现第二处阶段映射即失败；
4. 前端漏斗（R-05 已透传 `stage_code`）、筛选、看板同步。

## 六、影响面

| 维度 | 影响 |
|---|---|
| 表结构 | stage 语义迁移（终态 5/6→7/8）+ 列注释（冻结表，需 RFC） |
| 后端 | 5 文件收敛；自动推进点 stage 3 不变；守卫规则更新 |
| 前端 / 报表 | 漏斗、赢单率、阶段分布口径统一 |
| 数据 | 存量 stage 重映射，先干跑 |
| CI / 基线 | 迁移后重生成基线 + N-05 |

## 七、风险与回滚

- 风险：硬编码「5=成交」的服务（`opportunityService` 多处）在终态右移后错位。
  对策：全部收敛到字典后再迁数据；干跑核对每个商机新阶段。
- 回滚：字典与引用可回退；数据迁移保留映射表，可逆。

## 八、验收标准

- [ ] 阶段字典单一事实源，全仓无第二处映射（含截断形态）。
- [ ] 8 阶段漏斗 / 报表 / 搜索 / 团队看板口径一致。
- [ ] 存量数据映射干跑无丢失、错位（成交→7、流失→8）。

## 九、待确认问题

**决策记录（2026-09-24，方案 A）**：

1. 8 阶段名称 / 顺序定稿：新增「**合同审批 contract_review（5）/ 合同签署 contract_signing（6）**」，成交 7、流失 8。
2. 「流失」占第 8 阶段（不走旁路）。
3. 阶段与合同状态机（RFC-R10）在审批/签署/成交环节联动，动作权限随 R10 一起实施。
